\subsection{Training Time and Memory}
\label{app:experimental-config:resources:memory}

Experiments were run on whichever GPU was available: NVIDIA V100 (16 GB), GV100 (32 GB), or P40 (24 GB), always one GPU per run, batch size 64 with gradient accumulation $\times 2$ (effective batch 128). Approximate wall-clock time per seed: ${\sim}10$--16\,h on GV100, ${\sim}18$--28\,h on V100 or P40. Typical convergence occurs at epoch 15--25 of the 200-epoch maximum.

Memory usage: Model FP32 (${\sim}0.28$ GB) + AdamW states (${\sim}0.55$ GB) + activations (${\sim}6$--10 GB at batch 64) $\approx$ 7--11 GB in full precision. With mixed-precision training (AMP), peak memory drops to $\approx$ 5--7 GB, comfortably within the V100's 16 GB, the tightest GPU used.

Primary evaluation and ablation experiments use random seed 42. Robustness checks for the separation loss ablation ($\lambda \in \{0.01, 0.02\}$) are performed across three seeds (42, 123, 456) as described in Section~\ref{sec:results:cifar}. The seed is initialised with:

\begin{verbatim}
import random, numpy as np, torch

def set_seed(seed=42):
    random.seed(seed)
    np.random.seed(seed)
    torch.manual_seed(seed)
    torch.cuda.manual_seed_all(seed)
    torch.backends.cudnn.deterministic = True
    torch.backends.cudnn.benchmark = False
\end{verbatim}

Complete experiment metadata is logged to Weights \& Biases including: Git commit hash, all hyperparameters, training/validation metrics per epoch, hardware utilisation, and checkpoint paths.

Dataset versions: CIFAR-10 (torchvision 0.15.2), CIFAR-100 (torchvision 0.15.2), SVHN (format 2, cropped), Textures (DTD all 47 categories), FashionMNIST (torchvision, resized to $32 \times 32$, greyscale to RGB), and Places365 (10,000 scene images resized to $32 \times 32$).

All code is version controlled via Git with commit hashes logged for every experiment. Configuration files (including all command-line overrides) are saved with results for exact reproduction.

Two design asymmetries are deliberate and documented above: (i)~the $K$-, timestep-, and scoring-strategy ablations use the seed-42 $\lambda{=}0.01$ checkpoint rather than the final $\lambda{=}0.02$ model for compute-budget reasons, and (ii)~the external OOD evaluation is single-seed (seed~42) but uses $K{=}100$ to reduce Monte Carlo variance in the reported means. Both are surfaced verbatim in Chapter~\ref{chap:results} where the affected numbers first appear.
